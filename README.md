# 赛鸽登记站（档案 / 血统 / 成绩 + 鸽舍环境监控告警）

运行：

```bash
npm start        # 默认 http://localhost:3024
```

- 旧入口（原样保留）：`/` —— 档案、血统查询、转让、归巢成绩；旧 API 仍为 `/api/pigeons/*`。
- 环境监控台（新）：`/monitor` —— 鸽棚/设备/传感器登记、阈值与维护期、分批上报、告警处置。
- 两页互相提供链接，旧入口行为不变。

## 环境监控能力

- **登记**：鸽棚（可配离线超时）、设备（归属棚）、环境传感器（温度/湿度/氨气，挂在设备下）。
- **分批上报** `POST /api/monitor/ingest`：一批多条读数；
  - 相同 `batchId` 重复提交整体幂等，原样回放首次结果，换内容重放也不入库；
  - 批内先整批校验，任一记录非法则整体拒绝、无半成品落库；
  - 批内乱序按读数时间戳排序后处理；跨批的旧读数只进历史，**绝不覆盖较新状态**。
- **告警引擎**：阈值按 **棚级 / 设备级（优先）/ 时段（支持跨午夜）** 配置，可设连续越限次数；
  - 连续越限达到次数才告警，短时抖动不告警；读数回到区间即**自动结束（recovered）**；
  - **维护期内不告警**，且维护前累计的越限次数清零。
- **告警处置**：确认、指派、升级、关闭；
  - 只有恢复后（recovered）才能关闭；
  - 重复或并发处置只成功一次（服务端写事务串行化 + 状态机前置校验），全部动作留痕。
- **离线超时**：超时未上报自动标记离线并记录事件，恢复上报自动上线。
- **持久化**：原子写（临时文件 + rename）+ 写队列串行化；写入失败整体回滚；
  重启后设备、读数、阈值、维护期、告警、处置记录、时间线均可查（`data/monitor.json`）。
